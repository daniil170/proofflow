# ProofFlow Telegram Bot (`bot`)

Telegram-бот сервиса ProofFlow для сбора заявок на закрытое бета-тестирование, поддержки пользователей, частых вопросов, сбора идей с голосованием и безопасной привязки Telegram-аккаунтов пользователей продукта.

## 1. Команды бота

При старте бота в Telegram регистрируются следующие команды через `setMyCommands`:
- `/menu` — Главное меню с быстрым переходом ко всем функциям.
- `/support` — Создание обращения в службу поддержки.
- `/idea` — Предложить новую функцию или улучшение продукта.
- `/ideas` — Публичный список идей участников с голосованием.
- `/faq` — Частые вопросы и ответы о ProofFlow.
- `/start` — Подача заявки в бета-тестирование или привязка аккаунта через deep link (`link_<token>`).
- `/stop` — Отписка от рассылок и уведомлений бота (ответы поддержки по открытым обращениям продолжают приходить).
- `/delete` — Каскадное удаление всех данных пользователя (заявка, тикеты поддержки, предложенные идеи, отзыв всех голосов с пересчётом счетчиков).
- `/help` — Справочная информация по доступным командам.

## 2. Поддержка (`features/support`)

- Пошаговый сбор обращения: выбор темы («Вопрос про бету или доступ», «Проблема в продукте», «Другое»), текстовое описание (до 2000 символов), поддержка фото, голосовых сообщений и документов (до 5 вложений). Файлы не скачиваются, сохраняются только `file_id` и тип.
- Карточка подтверждения перед отправкой («Отправить», «Отмена»).
- Уведомление администратора в `ADMIN_CHAT_ID` с номером обращения, ссылкой на пользователя, темой, текстом, вложениями (через `copyMessage`) и кнопкой закрытия.
- Ответ администратора: обычный reply на сообщение-уведомление в `ADMIN_CHAT_ID`. Бот пересылает пользователю текст, фото или голосовое с заголовком «Ответ от команды ProofFlow».
- Обработка блокировки: если пользователь заблокировал бота, администратор получает уведомление об ошибке доставки.
- Продолжение диалога: пока обращение открыто (`open`), любые новые сообщения пользователя в течение 24 часов автоматически добавляются к нему и пересылаются администратору.
- Пользователь или администратор могут закрыть обращение кнопкой.

## 3. Сбор идей и голосование (`features/ideas`)

- Пошаговое предложение идеи: выбор категории («Новая функция», «Улучшение того, что есть», «Интеграция», «Другое»), описание текстом (до 2000 символов) или голосовым сообщением, опциональный шаг контекста текущей задачи («Пропустить»).
- Санитайзинг: ссылки в публичных идеях обезвреживаются (`[.]`), чтобы исключить кликабельный спам.
- Модерация: в `ADMIN_CHAT_ID` администратор получает карточку идеи с кнопками «Показать всем» (`public`) и «Скрыть» (`hidden`).
- Публичный список `/ideas`: выводит топ текстовых одобренных идей (по 5 на страницу) с пагинацией.
- Голосование: кнопка «Мне тоже нужно ({count})». Нажатие переключает голос (toggle), автор не может голосовать за свою идею.

## 4. Каскадное удаление данных (`/delete`)

По команде `/delete` и подтверждению происходит:
1. Удаление заявки пользователя на бета-тестирование.
2. Удаление всех тикетов поддержки пользователя.
3. Удаление всех предложенных идей пользователя.
4. Отзыв всех голосов пользователя за идеи других участников с декрементом их счетчиков `votesCount`.
5. Сброс активных сессий пользователя.

## 6. Запуск и тестирование

```bash
# Установка зависимостей
npm install

# Запуск линтера
npm run lint

# Сборка TypeScript
npm run build

# Запуск тестов vitest
npm test

# Запуск в режиме разработки (watch)
npm run dev
```
